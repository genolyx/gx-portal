External Create Order API

Create Gx-Portal analysis orders from an external portal using an API key. Fastq files can be supplied as HTTP(S) URLs (downloaded into shared FASTQ directories) or as absolute paths already on disk.

Auth Endpoints Common fields Carrier Screening Whole Exome Health Screening Single-gene NIPT FASTQ download Examples Errors

Authentication

Send the API key on every request:

X-API-Key: <EXTERNAL_API_KEY>

Alternatively: Authorization: ApiKey <EXTERNAL_API_KEY>

Keys and client mapping are configured in the API .env:

  • EXTERNAL_API_KEY — shared secret
  • EXTERNAL_API_CLIENT_ID — portal clients.id that owns created orders (must have order_prefix)
  • FASTQ_DIR_CARRIER / FASTQ_DIR_SGNIPT — where the API writes downloads
  • FASTQ_DIR_CARRIER_DAEMON / FASTQ_DIR_SGNIPT_DAEMON — optional; host paths stored on the order when API (Docker) and gx-daemon (host) see different absolute paths for the same bind mount

Missing/invalid key → 401. Placeholder / empty EXTERNAL_API_KEY → 503.

Base URLs

  • Production (nginx): http://<host>:8090/api/external
  • Local API: http://localhost:4000/external

Endpoints

MethodPathDescription
POST /orders/:serviceCode Create order. serviceCode: carrier_screening | whole_exome | health_screening | sgnipt
GET /orders/:orderId Get order (scoped to the API key’s client)
POST /orders/:orderId/start Start pipeline for a saved order

Order IDs are allocated by Gx-Portal as {CS|WE|HS|SN}{clientPrefix}{YYMM}{seq4} (e.g. CSGX26080001). Do not send your own order_id.

Create returns a draft (SAVED) unless "start": true is set in the body.

Service: whole_exome

Same field schema as Carrier Screening. Differences:

  • params.carrier.package_code forced to WholeExome
  • Required: params.wes_panel_id

Service: health_screening

Same field schema as Carrier Screening. Differences:

  • params.carrier.package_code forced to HealthScreening
  • Additional optional top-level: params.include_apoe_pgx (boolean)
  • Required: params.wes_panel_id

FASTQ URL download

  1. Portal allocates order_id.
  2. Downloads each URL into {FASTQ_DIR_*}/{orderId}/<basename>.
  3. Sets fastq_r1_path / fastq_r2_path on the daemon save payload.
  • Exome family → FASTQ_DIR_CARRIER
  • sgNIPT → FASTQ_DIR_SGNIPT

These directories must be the same roots gx-daemon uses for FASTQ browse. Large downloads may take several minutes; nginx timeout for /api/external/ is 30 minutes.

Examples

Carrier Screening (with FASTQ URLs)

curl -X POST 'http://localhost:8090/api/external/orders/carrier_screening' \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: YOUR_KEY' \
  -d '{
    "description": "ext-ref-001",
    "fastq_r1_url": "https://example.com/sample_R1.fastq.gz",
    "fastq_r2_url": "https://example.com/sample_R2.fastq.gz",
    "params": {
      "wes_panel_id": "Carrier_302",
      "carrier": {
        "patient_name": "Jane Doe",
        "patient_birth": "1990-01-15",
        "patient_gender": "Female",
        "hospital_name": "Genolyx Hospital",
        "doctor": "Dr. Kim",
        "sample_collection_date": "2026-08-01",
        "report_language": "EN",
        "report_type": "Portal"
      }
    }
  }'

Start after create

# either set "start": true on create, or:
curl -X POST 'http://localhost:8090/api/external/orders/CSGX26080001/start' \
  -H 'X-API-Key: YOUR_KEY'
